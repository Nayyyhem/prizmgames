UI Shapes

v1.0.0 Manual · PRIZM GAMES

One component for Unity UI. Add a UIShape to any UI element and you get rounded, octagonal or slanted shapes with fill, gradients, textures, drop shadow, inner shadow, glow, outline, bevel and background blur, plus soft masking, progress wipes and per-state button styling. No sprites, no 9-slices, no render textures. Everything stays crisp at any resolution.

Requirements

  • Unity 2022.3 LTS or newer, and a uGUI Canvas. Nothing else is required.
  • Built-in, URP and HDRP all supported, and UI looks identical on all three. Background Blur needs a one-time setup step on URP (see its section).
  • Shader Model 3.0+: mobile (GLES 3.0 / Metal / Vulkan), desktop, consoles and VR. OpenGL ES 2.0 is not supported.

Demo scenes live in UI Shapes/Demo/, one folder per pipeline, each with a full showcase scene and a Background Blur scene. Open the folder matching your project and delete the others. The labels use TextMeshPro, so import TMP Essentials when Unity offers to. UI Shapes itself has no TMP dependency. Demo scenes from a pipeline you don't use will show pink materials, which is expected.

Quick Start

  1. Select a UI GameObject, or create an empty one under your Canvas.
  2. Add Component ▸ UI ▸ UI Shape.
  3. Tick the effects you want in the inspector and tune them. The component builds and manages everything itself.

To make it interactive, click Add Button or Add Toggle next to the Selectable field at the top of the inspector. See Button States.

TipYou can also use UIShape as a decorator: leave Fill off and put it on (or beside) an existing Image to wrap it in a shadow, glow or outline.

Using the Inspector

Each effect is a collapsible module, styled like Unity's Particle System. The checkbox in the module header is the on/off switch, and clicking the bar expands the settings. You can expand a module while it's off to look at its settings; they show read-only until you enable it.

Most effects share the same handful of controls at the top of their module, described once under Common Controls. Each effect's own section below lists only the settings specific to it.

All sizes and distances are in canvas units, and all angles are in degrees.

Shape

FieldWhat it does
Corner StyleSharp (default) is a plain rectangle, and hides the radius controls since they don't apply. Rounded gives circular corner arcs. Octagonal cuts each corner off as a straight 45° chamfer.
Border ModeHow the corner radius is shared out. Uniform uses one radius for all four corners. Round auto-sizes it to half the short side, so squares become circles and long rectangles become pills. Free gives a separate radius per corner.
Corner RadiusThe arc radius on Rounded, or the chamfer size on Octagonal. Radii that would overlap along an edge scale down together, the same way CSS border-radius does.

Every effect follows the corner style you pick, so fill, outline, shadows, glow and bevel always share one silhouette. Style and radii animate and can be overridden per button state, and Sharp to Rounded transitions collapse the corners smoothly. All three styles cost the same, so pick by looks.

Skew

Turn the Skew module on to slant the shape like italic text. It's purely visual, so the RectTransform, layout and anchoring don't change, and every effect slants with it, still anti-aliased.

FieldWhat it does
Skew AxisHorizontal or Vertical.
Skew AngleThe slant in degrees. 0° is upright.
Skew ModeParallel: both edges share the angle, giving a parallelogram. This is the classic italic slant, and the default.
Mirrored: the opposite edge takes the negative angle, giving a symmetric trapezoid. Good for banners, ribbons and fake-perspective panels.
Custom: an angle per edge (Left and Right, or Bottom and Top on a vertical skew) for an asymmetric trapezoid.

Because the module has its own enable, you can keep an angle set and just switch the slant on and off, including per button state, where the angle fades in and out smoothly.

A trapezoid narrows as the angle grows and stops on its own before the edges cross, settling into a clean triangle. How steep you can go depends on the element's proportions: a tall element takes a much steeper angle than a short one.

Soft masks, Background Blur and click detection all follow the slanted outline.

LimitationSoft masking a skewed shape assumes the mask and its canvas aren't rotated.

Common Controls

These four settings appear on most effect modules. Each effect section below says which of them it has, then lists its own specific fields.

FieldWhat it does
Color ModeWhether the effect uses a Single Color or a gradient. See below.
Opacity0 to 1, fading that effect alone. Layers on top of the colour's own alpha.
Blend ModeHow the effect composites over what's beneath it. Normal covers, Additive brightens (good for glows and bevel highlights), and Multiply darkens (good for bevel shadows and tinted overlays).
Intensity0.1 to 10, an alpha multiplier. Values above 1 make a soft effect's core denser without making it any bigger, which is the difference between a faint haze and a solid core at the same radius. Only the three soft effects have it.

Gradients

Wherever Color Mode offers a gradient, the choices are Vertical (top to bottom), Horizontal (left to right), or Custom Angle, which adds an Angle slider (0° puts the end colour on the right, 90° on top).

Fill uses Unity's own gradient editor: click the Gradient field and add as many colour and alpha stops as you like, anywhere along the ramp. Set the gradient's own mode to Fixed for hard-edged bands instead of a smooth blend. Every other effect (Texture, Drop Shadow, Inner Shadow, Glow, Outline) keeps a simpler start and end colour, which is what those effects are normally used for.

Colours carry alpha, so a transparent stop gives a clean fade-out, and alpha stops can sit at different positions from the colour stops. Colours blend perceptually, matching Photoshop, Figma and CSS. Gradients are free: same draw call, no extra texture, and they work with masking and state transitions, including cross-fading between a single colour and a gradient, or between two gradients with different numbers of stops.

NoteThe Animator can key an effect's Color (in Single Color mode) but not a Gradient, which Unity's animation system cannot handle. To animate a Fill gradient, put the gradients on button states and let the state transition cross-fade them, or swap them from a script.
NoteMultiply-blended effects render in a separate draw call from Normal and Additive ones. It's a small cost, and worth it for the classic bevel look, but it's the one blend mode with a performance side.

Fill

The shape's interior, as a single colour or a multi-stop gradient.

Common controls: Color Mode and Opacity. Fill has no blend mode or intensity of its own, since it's the bottom layer everything else composites over. Textures are a separate module, covered next.

Texture

An optional sprite drawn on top of the Fill and clipped to the shape's corners, like an Image layered over the fill. Enable it independently of Fill. With no sprite assigned it draws a plain white rect, which the tint below turns into a plain coloured layer.

Common controls: Color Mode, Blend Mode and Opacity. The colour here is a tint: it multiplies the sprite's own colours rather than replacing them, exactly like Image.color. White, the default, leaves the sprite untouched, and a greyscale or white sprite can be recoloured freely. Choosing a gradient Color Mode gives a two-colour tint gradient across the shape, so one sprite can fade between two colours. The tint's alpha multiplies with Opacity, which is how you fade a texture out across the shape.

FieldWhat it does
TextureThe sprite to draw. Leave it empty to draw nothing.
Texture FitHow the sprite fits the rect when the aspect ratios don't match. See the table below.
Pixels Per Unit MultiplierConstant Size only. Scales the tile's on-screen size, matching Image.pixelsPerUnitMultiplier.
GrayscaleStrips the sprite's colour before the tint is applied. On its own it greys an image out, which is what you want on a Disabled state. Combined with a tint it recolours the image through that single colour.
SepiaTick Grayscale and set the tint to a warm brown. Because the colour is stripped first, the tint has nothing left to fight, so the whole image comes through in that one hue. A blue tint gives a cyanotype, a green one gives a night-vision look, and a gradient tint fades the image between two hues. Without Grayscale the same tint only darkens the colours already there.

Texture Fit handles mismatched aspect ratios:

ModeBehaviour
Stretch (default)Scales to fill, ignoring aspect ratio.
Aspect FitKeeps aspect and fits inside the shape. The margin is transparent, like Image.preserveAspect.
Aspect FillKeeps aspect, scales up to cover the shape, crops the overflow.
Constant SizeA fixed on-screen texel size, tiled to cover the rect. Needs a non-atlas sprite with Wrap Mode: Repeat, and the inspector warns if the sprite doesn't qualify. The tile size comes from the sprite's Pixels Per Unit, the Canvas's Reference Pixels Per Unit, and the multiplier above.

Textures always render upright. They never shear with a skewed shape, though the silhouette still clips them. The tint gradient does follow the shape, so it stays aligned with the fill's gradient on a skewed or tapered shape. Every Texture field can be overridden per state and animated, so states can swap the sprite, the fit, the tint or the opacity. Grayscale is on or off rather than a 0 to 1 amount, so it switches at the start of a state transition instead of fading across it, the same way Texture Fit and the blend modes switch.

Drop Shadow

A soft shadow behind the element.

Common controls: Color Mode, Opacity, Blend Mode and Intensity.

FieldWhat it does
RadiusBlur distance.
DistanceHow far the shadow is offset from the shape.
AngleWhich way it's offset. 0° is right, 90° is up.
SpreadGrows or shrinks the shadow before blurring.

The shadow is cut out of the shape's interior, so a semi-transparent glass panel never shows its own shadow through itself.

Inner Shadow

A soft shadow drawn inside the shape's edge, for a recessed look. It covers the outer edge completely, so no rim of fill colour peeks through.

Common controls: Color Mode, Opacity, Blend Mode and Intensity.

FieldWhat it does
RadiusBlur distance.
DistanceHow far the shadow is offset inside the shape.
AngleWhich way it's offset. 0° is right, 90° is up.
SpreadPositive values thicken the shadow on all sides.

Glow

A halo around the shape, additive by default. It's centred, so unlike the shadows it has no distance or angle, and like the drop shadow it renders only outside the shape.

Common controls: Color Mode, Opacity, Blend Mode and Intensity.

FieldWhat it does
RadiusHow far the glow reaches out from the shape.
SpreadGrows or shrinks the glow before blurring.

Outline

A stroke on the shape's edge.

Common controls: Color Mode, Opacity and Blend Mode. The outline is a hard-edged effect, so it has no intensity.

FieldWhat it does
PlacementInside, Outside or Centered on the edge.
WidthStroke thickness. It stays even on skewed shapes.
Softness0 for a crisp stroke, higher to feather it.
DistancePushes the stroke further out, for a detached ring.

On a sharp-cornered shape, Outside and Center strokes miter to a point. With a radius, the outer edge grows to radius + width, the way design tools stroke a rounded rectangle.

NoteA soft Outside outline can leave a very faint trace where its falloff crosses the fill's edge. Inside or Center placement avoids it.

Bevel

A Photoshop-style inner bevel: a lit band along the edge, with a highlight on the light-facing side and a shadow opposite, wrapping around rounded corners.

Bevel has no single colour of its own. Instead the highlight and the shadow each get their own Color, Opacity and Blend Mode, so you can tune the two halves independently. The defaults are additive white and normal black; set the shadow to Multiply for the classic Photoshop look.

FieldWhat it does
WidthThe band size.
DepthShading strength.
SoftnessFeathers the band and rounds the corner transitions. 0 gives a crisp chisel with hard miter lines.
AngleLight direction. The default 135° is Photoshop's up-left.
InvertFlips the lighting so the shape reads as pressed in. Handy for a pressed button state.
Highlight Color
Highlight Opacity
Highlight Blend Mode		The lit side of the band. Additive white by default.
Shadow Color
Shadow Opacity
Shadow Blend Mode		The unlit side. Normal black by default.

Background Blur

Frosted glass, blurring whatever is rendered behind the shape. Pair it with a semi-transparent Fill for tinted glass. It's clipped to the shape's corners, respects soft masks, and composes correctly where panels overlap.

Blur has none of the common controls. Its three settings are its own, and the tint comes from the Fill module underneath.

FieldWhat it does
RadiusBlur strength.
Blur OpacityMixes between the sharp and the blurred background. 1 is fully blurred. This is a mix, not a fade to transparent, so lowering it lets the sharp background show through rather than making the panel see-through.
QualityThe blur's sample count: High (32 taps), Medium (16) or Low (8). Lower counts cost proportionally less GPU time and stay smooth even at large radii, with the difference showing mostly on busy, high-contrast backdrops. Use Low or Medium on mobile.

Setup Per Pipeline

PipelineSetup
Built-inWorks out of the box, and is the only pipeline that also blurs UI behind the panel, including elements on the same canvas.
URPOne-time setup: select your URP Renderer asset (under your URP Asset's Renderer List) and add the Renderer Feature UI Shapes Background Blur Feature. Until you do, blur panels stay invisible and the inspector shows a reminder. The feature costs nothing on frames with no blur panel, so it's safe to leave installed. Its Capture Resolution (default Half) is your main mobile lever: Half looks all but identical to Full, and Quarter is cheaper still and fine for large radii.
HDRPNo setup. It's handled automatically.
URP / HDRPThe background is captured once per camera, after post-processing, so a panel blurs the finished world image. But UI drawn by that camera, and other elements on the same canvas, are not included. For UI-over-UI blur on URP or HDRP, render the content behind the panel with a separate camera.
PerformanceBackground Blur is by far the most expensive effect. On a mobile-class GPU (Switch included), a large panel can cost more GPU time than every other effect combined.

Your levers, in order of impact: URP's Capture Resolution, the per-shape Quality, and the panel's on-screen size. Great for menus and dialogs, but budget carefully before putting it on a permanent HUD, and prefer a few large panels over many small ones. Not supported in VR, though every other effect is.

Progress

Reveal a fraction of the shape, like an Image's Fill Amount, for radial timers, linear bars and cooldown sweeps. Off by default; turn the module on with its header checkbox.

FieldWhat it does
Amount0 to 1, how much shows. This is the value you animate or drive from script (ProgressAmount).
MethodRadial is a 360° sweep (pie or clock). Linear is a straight wipe.
OriginWhere the fill starts: the edge it grows from on Linear, or the starting angle on Radial.
ClockwiseRadial only. Reverses direction.
TargetsWhich effects get trimmed: any mix of Fill, Outline, Glow, Drop Shadow, Inner Shadow and Bevel. Unticked effects always draw in full, so you can wipe the Fill while a static Outline frames the whole shape. Background Blur is never trimmed.

The wipe has smooth anti-aliased edges, adds no draw calls, and works with masking, the Animator and button states. Gradients, textures and bevels are revealed exactly as far as the Amount.

Masking

The Masking foldout turns the shape into a mask for its children.

ModeWhat it does
NoneNo masking.
SimpleAdd a Unity Mask component to the same GameObject and keep Fill enabled, and the shape becomes the stencil. Hard edges, clips every descendant.
SoftAnti-aliased clipping with no stencil and no RenderTexture. Remove any Mask or RectMask2D on the object first, since Soft replaces them. The inspector warns if one is still there.

Soft clips child Images and RawImages, child UI Shapes (fills, shadows, glows and outlines all follow the mask, which is ideal for scroll views of cards), and TextMeshPro text when TMP is installed. It also culls children that scroll fully out of view, like RectMask2D, so a long list only pays for the rows on screen.

Soft mode adds two settings that shape the clip area itself. Both take four values, Left, Right, Top and Bottom, so each side can differ:

FieldWhat it does
PaddingInsets the clip like RectMask2D's padding. Positive values pull that side inward; negative values push it out so children can spill past the shape. Corner radii are unchanged.
SoftnessFades the clip out over that distance instead of ending at a hard edge. Top and bottom softness on a scrolling list is the classic use: rows dissolve at the viewport edges with no gradient overlay image. A side left at 0 keeps its crisp edge, and adjacent soft sides meet cleanly in the corner.

Both are component-level settings. They're the same for every button state, aren't part of a saved style, and can be driven from script (MaskPadding, MaskSoftness).

Which to use?Soft is the better-looking option and right for the common case: one scrolling list or panel of Images, UI Shapes and text. Use Simple for nested masks (only one Soft mask can be active at a time), a rotated mask, children with custom materials or third-party graphics (Soft clips plain Images, RawImages, UI Shapes and TMP text, while a stencil clips everything), or TMP text that needs bevel, glow, lighting or a textured face inside the mask.

Other things to know about Soft masking:

  • Clipping is visual only, so a clipped child still receives pointer events. Set Raycast Mode to Off on elements scrolled out of view.
  • Soft-clipped TMP text keeps its face, outline and underlay (drop shadow) settings. Effects that only exist in TMP's full Distance Field shader are not applied while clipped, and inline sprites and fallback fonts aren't clipped.
  • Your children's materials and settings are never modified on disk. Clipping is injected at render time only, so switching presets, saving and entering play mode all behave as usual.

Maskable, the last field in the module, works in every masking mode including None. It controls whether this shape's own effects can be clipped by an ancestor Mask or RectMask2D, so turn it off to let a big shadow or glow spill outside a masked parent.

Clicks & Raycasting

Whether the shape catches pointer events is set at the top of the inspector, next to Selectable. Most shapes show a Raycast Target checkbox. A shape whose Selectable lives on a different UI Shape, such as a child checkmark, shows a Raycast Mode dropdown instead:

ModeWhat it does
Follow (default)Catches nothing itself, but mirrors the parent shape's Highlighted, Pressed and Selected look across the whole parent. That's how a checkmark lights up with its toggle.
OnHit-tests its own bounds and computes its own state.
OffInert, purely decorative.

Hit-testing matches the shape you see, not its bounding rectangle. Rounded and octagonal corners, slant and taper are all accounted for, so a click just outside a corner falls through to whatever's behind. Drop shadow and glow aren't clickable.

This only ever applies to the shape itself. Anything parented under it, whether buttons, images, text or other shapes, keeps its own pointer behaviour, so turning Raycast Target off makes the shape click-through without affecting its children.

Button States

A UI Shape can restyle itself per Selectable state, with no sprite swaps.

  1. Assign your Button (or any Selectable) to Selectable, or click Add Button / Add Toggle to add and assign one in a single step. UI Shapes sets that Selectable's own Transition and Navigation to None, since this component drives the visuals, and turns Raycast Target on. Switch Navigation back on afterwards if you need keyboard or controller support.
  2. A row of tabs appears: Normal · Highlighted · Pressed · Selected · Disabled. Normal is the shape's main setup, and the others hold per-state overrides.
  3. On a state tab, tick the checkbox next to any property you want to change there. Unticked properties follow Normal, and unticking one snaps it straight back, so there's nothing to reset by hand. A module's header checkbox is itself an override, which is how you switch an effect on or off for one state.
  4. Set Transition Duration (next to the Selectable field) to cross-fade between states; 0 is instant. Fades use unscaled time, so they keep working while the game is paused.

An orange bar in the left gutter marks every property, module header and tab that differs from Normal, like Unity's prefab override lines, so you can see what a state changes without opening it.

The selected tab is the live preview: the element on screen shows that state while you edit it, and switching back to Normal shows the base look. Previews are never saved.

State precedence matches Unity's Selectable: Disabled > Pressed > Selected > Highlighted > Normal.

Toggles

Assign a Toggle as the Selectable (or click Add Toggle) and an Off | On bar appears above the state tabs, so every interaction state can be authored separately for the unchecked and checked toggle.

  • Off is the ordinary state model: Off/Normal is the base look, and the other Off tabs override it.
  • On/Normal is the checked resting look, a set of overrides on top of the base.
  • Each On state falls back to On/Normal, then to the matching Off state, then to the base. For example, with Off/Normal dark grey and Off/Highlighted light grey, On/Highlighted starts out light grey. Set On/Normal's fill to green and On/Highlighted follows to green. Override On/Highlighted itself to light green and it stops inheriting. The inspector always shows the resolved value.
  • Checking and unchecking cross-fade with the same Transition Duration as any other state change.
  • Changes from code, including SetIsOnWithoutNotify and Toggle Group (radio button) switching, are picked up automatically. There's nothing to call.

Checkmarks

Add Toggle also creates a ready-made child Checkmark UI Shape, grey when off and green when on, driven by the same Toggle, so a fresh toggle works immediately. Restyle or delete it freely.

That's the general pattern for shape checkmarks: give a child UI Shape the same Toggle as its Selectable and author its On/Off looks. Sharing the Selectable also makes the checkmark follow the parent's Highlighted, Pressed and Selected state across the whole parent, so hovering anywhere on the toggle lights the checkmark too (see Raycast Mode).

NoteA UI Shape can't go in the Toggle's own Graphic field, because it isn't a uGUI Graphic. Use that field only if you'd rather have a plain Image checkmark that Unity fades for you.

Reusable Styles

Any tab, Normal or a state, can save its settings as a style asset and load them onto other shapes. The Style field at the top of each tab is the picker.

  • Save Style writes the current tab to a .asset file and loads it.
  • Assigning an existing style applies its settings to that tab.
  • While a style is loaded, editing the tab updates the asset automatically, and every other shape using it updates live. Editing the asset in its own inspector does the same.
  • Unload (or clearing the field) keeps the current values but stops syncing.
  • Create an empty style with Assets ▸ Create ▸ UI Shapes ▸ Style.

A style saved from Normal is a complete look, so loading it onto a state tab overrides every property there. A style saved from a state tab is a delta: it stores only that state's overrides, so loading it onto another button changes just those properties and leaves the rest following that button's own Normal. That's what makes a shared "hover style" or "pressed style" reusable across buttons that look nothing alike.

Styles are an authoring convenience only. Nothing reads them at runtime, so there's no performance cost, and deleting a style asset never breaks a build.

Animation & Scripting

Every setting is a plain serialized field, so the Animator can drive it directly: corner radius, colours, shadow distance, anything. Animated values sit under state overrides, so animation drives the base look and states override on top.

From code, everything lives in the PrizmGames.UIShapes namespace:

using PrizmGames.UIShapes;

var shape = GetComponent<UIShape>();
shape.CornerRadius   = 24f;          // properties push to the shader automatically
shape.FillColor      = Color.white;
shape.Glow           = true;
shape.ShadowOpacity  = 0.6f;
shape.SetBorderMode(UIShape.BorderMode.Round);

shape.Progress       = true;         // radial timer
shape.ProgressAmount = timeLeft / duration;
  • PascalCase properties mirror the inspector fields (CornerRadius, FillColor, ShadowRadius, TextureSprite, SkewAngle and so on) and mark the shape dirty on write.
  • Fill's gradient is FillGradient (the mode), FillGradientColors (a standard UnityEngine.Gradient) and FillGradientAngle. Assigning FillGradientColors copies the gradient in, so the shape never shares your instance; if you instead mutate the returned gradient in place, call shape.SetDirty().
  • The two-colour effects use a trio each: ShadowGradient, ShadowColor2, ShadowGradientAngle, and likewise for InnerShadow…, Glow… and Outline…. The Texture tint follows the same pattern: TextureColor, TextureGradient, TextureColor2, TextureGradientAngle, plus TextureGrayscale.
  • Enum settings use a Set… method instead of a property (SetCornerStyle, SetBorderMode, SetSkewAxis, SetSkewMode, SetTextureFit, SetProgressMethod, SetProgressOrigin, SetProgressTargets), because a property would collide with the enum's own name.
  • shape.CurrentState reads the active state. shape.GetStyle(state) returns an Off-column override block, and shape.GetOnStyle(state) the checked column's.
  • If you set the public camelCase fields directly, call shape.SetDirty() afterwards.

Performance & Platforms

Each enabled effect draws one quad, and effects of the same kind batch together across the whole canvas, so a canvas costs at most one draw call per effect kind in use, however many shapes it holds. A screenful of static shapes costs almost nothing on the CPU. The thing to budget is painted area: transparent UI doesn't occlude, so every effect quad costs its full on-screen size whether it ends up visible or buried.

  • Shadow and glow Radius directly sets how many pixels the effect covers. On mobile, VR and Switch, prefer proportionate radii over full-screen glows, especially in long scrolling lists.
  • Put shadows on containers rather than on every element inside them.
  • Keep effect-heavy UI on its own Canvas, which is good uGUI practice anyway.
  • Soft-masked scroll views cull rows that scroll out of view, so long lists stay cheap.

Mobile. Fully supported on GLES 3.0+, Metal and Vulkan. As a scale reference, on a 2023 budget Android phone a large panel covering roughly a fifth of the screen measures about 1 ms of GPU time for Fill or Outline, and around 3 ms for each soft effect (Drop Shadow, Inner Shadow, Glow, Bevel). Cost scales with area, so ordinary buttons and cards are far cheaper. Background Blur has its own budget, covered in its section.

VR. Works with Single Pass Instanced rendering. Note that Unity doesn't render Screen Space – Overlay canvases in VR at all, so use World Space or Screen Space – Camera, as with any uGUI content. Background Blur isn't supported in VR.

Consoles. No platform-specific code, and the shaders compile through Unity's standard pipeline for every target. On Switch, treat performance like a mid-range mobile GPU.

Builds. Shaders are referenced by the component, so they're always included. There's no Always Included Shaders or Resources setup to do. Every per-frame path is allocation-free.

Troubleshooting

SymptomFix
"Shader not found" in the consoleThe files under UI Shapes/Shaders/ were moved or deleted. Reimport the package.
Background Blur does nothing on URPAdd the UI Shapes Background Blur Feature to your URP Renderer asset. The inspector shows the same reminder.
Background Blur shows a sharp backgroundUnity cached a stale shader compile. Right-click UI Shapes/Shaders and choose Reimport.
Background Blur doesn't blur other UI on URP / HDRPBy design, since the capture is taken after the camera finishes. Only Built-in blurs same-canvas UI.
Effects invisible in VRThe canvas is Screen Space – Overlay. Switch it to World Space.
Button states don't apply in play modeCheck that a Selectable is assigned and its own Transition is None. The inspector hints at both.
TMP text isn't clipped by a Soft maskThe TMP integration compiles only when a TMP package is installed. Check that TMP is present in the project.

Hidden objects named [UIShape] …The internal effect renderers. They're never saved into your scene or prefab and rebuild automatically, so don't edit them.

Using UI Shapes as a UPM Package

The UI Shapes folder is also a UPM package (com.prizmgames.uishapes). To reference it from another project, add this to that project's Packages/manifest.json:

"com.prizmgames.uishapes": "file:../path/to/UI Shapes/Assets/UI Shapes"
